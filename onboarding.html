IDT AI 아이디어 챌린지 · 2026-11-10

1. 문제 정의

신규 입사자와 PC 교체 직원은 업무를 시작하기 전에 반나절 가까이를 환경 세팅과 자료 찾기에 쓴다. 요즘은 MS365를 설치하지 않고 웹으로 쓰는 경우가 많아서 세팅 자체는 가벼워졌다. 진짜 문제는 "무엇을 봐야 하는지"를 여전히 사람에게 물어봐야 한다는 점이다.

누가지금 겪는 불편
신규 입사자MS365 웹, 그룹웨어, Jira/Confluence 주소를 하나씩 찾아 등록하고, 흩어진 매뉴얼을 직접 받아서 정리한다. Confluence 스페이스가 많아 내 업무에 필요한 문서를 고르기 어렵다.
선배 · 멘토"이 문서 어디 있어요?", "VPN 어떻게 켜요?" 같은 질문을 신입마다 반복해서 받는다.
IT 담당자계정과 접속 경로 안내를 매번 반복한다. 팀마다 안내 내용이 달라 표준화가 어렵다.
팀장신입이 실제 업무에 투입되기까지 시간이 걸리고, 온보딩 품질이 멘토 개인 역량에 좌우된다.

2. 솔루션 개요

설치나 로그인을 대신해 주는 기능은 기반일 뿐이다. 핵심은 소속 팀과 직무에 맞춰 AI가 자료를 선별 · 분류 · 요약하고, 이후 질문에도 답하는 것이다.

단계내용AI 역할
① 기본 세팅MS365 웹 바로가기, 그룹웨어, Jira/Confluence 북마크자동화 (기반)
② 맞춤 자료 선별소속 팀과 직무를 보고 필요한 매뉴얼과 Confluence 스페이스만 골라 다운로드AI 판단
③ 자동 폴더 정리받은 문서를 읽고 주제별로 분류 (01_필수규정 / 02_개발환경 / 03_프로젝트)AI 분류
④ 첫 주 가이드 생성이번 주에 읽을 문서 5개, 세팅할 것, 물어볼 사람 요약본 생성AI 요약
⑤ 온보딩 Q&A정리된 자료를 바탕으로 "VPN 어떻게 켜요?" 같은 질문에 답변RAG 챗봇

3. 시스템 구성

새로 만드는 것은 온보딩 에이전트와 AI 레이어 두 가지다. 사내 시스템은 지금 쓰는 것을 그대로 쓰고, 사용자 권한 안에서 읽기만 한다.

구성요소역할
에이전트 앱사용자 PC에서 실행되는 작은 프로그램. 바탕화면 폴더와 바로가기를 만들고, 진행 상황을 보여준다.
온보딩 에이전트①~⑤ 단계를 순서대로 실행하는 오케스트레이터. 어느 단계까지 끝났는지 저장해서, 중간에 실패해도 그 단계부터 다시 한다.
AI 레이어LLM이 문서 선별 · 분류 · 요약을 맡고, 벡터 DB가 Q&A 검색을 맡는다. 답변에는 항상 근거 문서 링크를 붙인다.
사내 시스템Entra ID에서 부서 · 직무 · 매니저 정보를, 나머지 시스템에서 문서 목록과 본문을 읽는다. 쓰기 작업은 하지 않는다.

MS365를 쓰고 있어 SSO는 Entra ID(구 Azure AD) 기준으로 그렸다. 실제 사내 인증 방식에 맞춰 조정한다.

4. 전체 처리 흐름

사용자가 하는 일은 처음 로그인과 마지막 확인뿐이다. 그 사이 4~8단계는 AI가 판단하고 처리한다.

파란 상자가 AI가 판단하는 단계다. 목표 소요 시간은 전체 10분 이내이며, 대부분은 문서 다운로드와 요약 생성 시간이다.

5. 단계별 상세

각 단계가 무엇을 받아서, 어떻게 처리하고, 무엇을 남기는지 정리했다.

① 기본 세팅

입력
SSO 로그인 결과 (사용자 이름, 부서, 직무)
처리
공통 바로가기 목록(MS365 웹, 그룹웨어, Jira, Confluence)에 부서별 추가 항목을 더해 바탕화면과 브라우저 북마크에 생성
출력
바탕화면 업무 바로가기 폴더, 브라우저 북마크 폴더
AI
사용하지 않음. 규칙 기반 자동화

② 맞춤 자료 선별

입력
부서 · 직무 · 매니저 정보, 접근 가능한 Confluence 스페이스와 그룹웨어 매뉴얼 목록 (제목, 라벨, 최근 수정일, 조회 수)
처리
1차로 규칙으로 후보를 줄인다 (전사 필수 문서 + 소속 팀 스페이스 + 최근 1년 내 수정). 2차로 LLM이 문서마다 "이 직무의 신입에게 첫 달에 필요한가"를 0~10점으로 매기고 이유를 한 줄로 남긴다.
출력
상위 N개 문서 목록 + 선정 이유 (예: 30개)
AI
관련도 판단. 문서 전체가 아니라 제목 · 요약 · 목차만 보내서 비용과 시간을 줄인다.

③ 자동 폴더 정리

입력
선별된 문서 파일과 본문 앞부분
처리
직무별로 미리 정한 분류 체계(예: 솔루션 엔지니어 → 01_필수규정 / 02_제품이해 / 03_구축 · 기술지원 / 04_고객사)에 LLM이 문서를 배정하고, 알아보기 쉬운 파일명으로 바꾼다.
출력
바탕화면 온보딩 자료 폴더 (주제별 하위 폴더)
AI
분류와 파일명 생성. 분류 체계를 고정해 두어서 사람마다 결과가 달라지지 않는다.

④ 첫 주 가이드 생성

입력
분류된 문서, 선정 이유, 매니저 · 팀원 정보
처리
정해진 템플릿(읽을 문서 · 세팅 체크리스트 · 물어볼 사람)에 맞춰 LLM이 요약본을 작성한다. 문서마다 3줄 요약을 붙인다.
출력
첫 주 가이드.docx (또는 Confluence 개인 페이지)
AI
요약과 우선순위 판단

⑤ 온보딩 Q&A

입력
선별된 문서 + 전사 FAQ
처리
문서를 문단 단위로 나눠 벡터 DB에 저장하고(RAG), 질문이 오면 관련 문단을 찾아 LLM이 답한다. 근거가 없으면 지어내지 않고 담당자를 안내한다.
출력
Teams 챗봇 또는 에이전트 앱 내 채팅 창
AI
검색 + 답변 생성. 모든 답변에 출처 문서 링크를 붙인다.

8. 보안 설계

원칙은 하나다. AI는 사용자가 이미 볼 수 있는 자료만, 읽기 전용으로 다룬다.

우려설계
계정 · 비밀번호 유출비밀번호는 저장하거나 대신 입력하지 않는다. SSO 위임 토큰만 쓰고, 토큰은 Windows 자격 증명 관리자에 보관한다.
권한 밖 문서 노출모든 조회는 사용자 본인 토큰으로 한다. 사용자가 원래 못 보는 문서는 에이전트도 못 본다.
사내 문서가 외부 AI로 전송사내 승인된 LLM 환경(기업용 계약, 학습 미사용 조건)만 쓴다. 선별 단계는 제목 · 목차만 보낸다.
AI가 틀린 답변근거 문서가 없으면 답하지 않고 담당자를 안내한다. 모든 답변에 출처를 표시한다.
시스템 변경 사고사내 시스템에는 쓰기 작업을 하지 않는다. 변경은 사용자 PC 안에서만 일어난다.

10. 로드맵

11. 리스크와 대응

리스크대응
사내 문서가 오래됐거나 중복이 많음최근 수정일을 선별 점수에 반영한다. 오래된 문서 목록을 문서 관리자에게 리포트로 주는 부가 효과도 있다.
그룹웨어 API가 없음그룹웨어 매뉴얼을 지정된 SharePoint 폴더로 모아두고 그곳을 읽는다.
AI 선별 결과가 부서 기대와 다름부서별 "필수 문서" 목록을 직접 지정할 수 있게 하고, AI는 나머지만 고른다.
LLM 사용 비용선별은 제목 · 목차만 사용하고 요약은 선별된 문서만 한다. 신입 1명당 처리량이 작아 비용 부담이 낮다.

  1. 0:00 빈 바탕화면: "오늘 입사한 솔루션 엔지니어 신입의 PC입니다."
  2. 0:20 에이전트 실행: 부서 "IDT부문 ITS1파트", 직무 "솔루션 엔지니어" 입력 (데모에서는 SSO 대신 직접 입력)
  3. 0:40 진행 화면: "후보 문서 120개 → AI 선별 30개 → 분류 중" 단계별 진행 표시
  4. 1:30 결과 확인: 바탕화면에 생긴 온보딩 자료 폴더를 열어 주제별 정리 결과를 보여줌
  5. 2:00 첫 주 가이드: 가이드 문서를 열고, 문서별 선정 이유와 3줄 요약을 보여줌

데모는 개인 테스트 스페이스의 샘플 문서로 진행한다. 실제 사내 문서는 쓰지 않는다.

14. 예상 질문

그냥 스크립트로 자동화하면 되는 것 아닌가요?

바로가기 생성 같은 ①단계는 스크립트로 충분하다. 하지만 "이 직무의 신입에게 어떤 문서가 필요한가"는 규칙으로 정하기 어렵고, 문서가 바뀔 때마다 규칙도 고쳐야 한다. 이 판단을 AI가 맡는 것이 핵심이다.

Intune이나 Autopilot 같은 기존 도구와 무엇이 다른가요?

그 도구들은 PC와 앱 설치를 관리한다. 이 제안은 그 위에서 "사람에게 맞는 자료와 안내"를 다룬다. 서로 겹치지 않고 함께 쓸 수 있다.

사내 문서를 외부 AI에 보내도 되나요?

사내에서 승인한 기업용 LLM 환경만 사용한다. 선별 단계는 제목과 목차만 보내고, 모델은 설정으로 사내 승인 모델로 바꿀 수 있다.

AI가 엉뚱한 문서를 고르면요?

부서별 필수 문서는 사람이 지정하고, AI는 나머지 추천만 맡는다. 선정 이유를 함께 보여주므로 잘못 고른 경우 바로 알 수 있다.

AI가 틀린 답을 하면요?

근거 문서에서 찾은 내용만 답하고, 모든 답변에 출처를 붙인다. 근거가 없으면 답하지 않고 담당자를 안내한다.

개발 기간과 비용은요?

PoC는 1~2주, 사내 파일럿은 추가로 한 달 정도를 예상한다. LLM 비용은 신입 1명당 처리 문서가 수십 건 수준이라 크지 않다.
