1. 개요

wiki-sync는 Confluence 스페이스를 로컬 Markdown 파일과 git 저장소로 양방향 동기화하는 명령줄 도구다. 사용자는 Git과 같은 명령(clone · pull · status · diff · push)으로 위키를 다루고, AI 코딩 도구로 여러 페이지를 한 번에 수정한다.

2. 배경과 문제

  • 같은 정보(버전, 서버 주소, 담당자)가 여러 페이지에 흩어져 있어 일괄 수정이 어렵고 누락이 생긴다.
  • 웹 에디터에는 여러 페이지에 걸친 변경을 검토(diff)하고 리뷰하는 흐름이 없다.
  • 개발자의 편집 도구(VS Code, 검색 · 치환, AI 코딩 도구)를 위키에 쓸 수 없다.
  • 기존 오픈소스는 단방향(로컬 → Confluence)이라 웹 편집과 함께 쓰기 어렵다.

3. 목표와 비목표

목표

  1. Confluence 스페이스를 로컬 파일로 받아오고, 로컬 변경을 안전하게 되돌려 올린다.
  2. 웹에서 먼저 바뀐 내용을 절대 덮어쓰지 않는다.
  3. 손대지 않은 페이지는 서식을 포함해 전혀 바뀌지 않는다.
  4. AI 도구가 다루기 쉬운 평범한 Markdown 파일 구조를 제공한다.

비목표 (이번 범위 밖)

  • 웹 에디터 대체. 웹 편집은 그대로 병행한다.
  • 모든 Confluence 매크로의 Markdown 변환. 모르는 매크로는 원본 보존으로 처리한다.
  • 권한 · 댓글 · 좋아요 · 페이지 속성(라벨 제외) 동기화
  • 실시간 자동 동기화(백그라운드 감시)
  • Confluence Data Center 지원 (확장 단계에서 검토)

4. 사용자

사용자특징주요 요구
개발자 · 엔지니어git과 터미널에 익숙함. 기술 문서를 자주 고침일괄 수정, diff 검토, AI 활용
문서 관리자 (파트 리더 등)스페이스 품질을 책임짐노후 문서 파악, 변경 리뷰
일반 웹 사용자도구를 쓰지 않고 웹에서만 편집내 웹 편집이 덮어써지지 않을 것

5. 사용자 스토리

ID스토리
US-01개발자로서, 팀 스페이스를 명령 하나로 로컬 폴더에 받아 VS Code로 열고 싶다.
US-02개발자로서, AI가 여러 페이지를 고친 뒤 무엇이 바뀌었는지 페이지별로 확인하고 싶다.
US-03개발자로서, 내가 고친 페이지만 올리고 손대지 않은 페이지는 건드리지 않고 싶다.
US-04웹 사용자로서, 누가 로컬 도구로 올려도 내가 방금 웹에서 고친 내용이 사라지지 않기를 바란다.
US-05개발자로서, 웹에서 다른 사람이 고친 내용을 받아 내 로컬 변경과 합치고 싶다.
US-06개발자로서, 새 .md 파일을 폴더에 두면 해당 위치의 새 페이지로 만들어지길 바란다.
US-07문서 관리자로서, 실제로 올리기 전에 어떤 페이지가 어떻게 바뀔지 미리 보고 싶다.
US-08개발자로서, 목차 · Jira 같은 매크로가 있는 페이지도 안심하고 고치고 싶다.

ID요구사항우선순위관련

FR-03로컬에서 수정 · 추가 · 삭제 · 이동된 페이지 목록을 보여준다.P0US-02

FR-05수정된 기존 페이지만 업로드한다. 변경 여부는 파일 해시로 판단한다.P0US-03
FR-06업로드 전 웹 버전을 확인해, 받은 버전과 다르면 해당 페이지를 건너뛰고 충돌로 보고한다.P0US-04
FR-07--dry-run으로 업로드 없이 변경 예정 목록과 버전 변화를 출력한다.P0US-07

FR-09웹 변경 페이지만 받아 로컬 변경과 git merge로 합친다.P1US-05
FR-10id가 없는 새 .md 파일을 폴더 위치에 맞는 부모 아래 새 페이지로 만든다.P1US-06
FR-11파일 이동 · 이름 변경을 감지해 웹 페이지의 부모 · 제목을 바꾼다.P1US-03
FR-12페이지 간 링크와 첨부 이미지를 상대 경로로 변환하고 되돌린다.P1US-08

7. 비기능 요구사항

ID분류요구사항
NFR-01안전성웹의 더 새로운 버전을 덮어쓰는 경우는 0건이어야 한다.
NFR-02무결성수정하지 않은 페이지는 업로드되지 않는다. 변환 왕복(받기 → 올리기 → 받기) 결과는 같아야 한다.
NFR-03성능페이지 500개 스페이스 clone을 5분 안에 끝낸다(목표). pull · push는 바뀐 페이지 수에 비례한다.
NFR-04복원력호출 제한(429)과 일시 오류(5xx)는 자동 재시도한다. 중간 실패 시 성공한 페이지의 상태는 보존된다.
NFR-05보안토큰은 OS 자격 증명 저장소에만 저장하며 파일 · 로그 · git에 남기지 않는다.
NFR-06호환성Windows 10/11 우선, macOS · Linux 동작. Confluence Cloud REST API v2. git 2.30 이상.
NFR-07사용성명령 이름과 출력은 git과 비슷하게 한다. 모든 오류 메시지는 다음 행동을 안내한다.
NFR-08유지보수변환기는 실제 페이지 샘플 기반 회귀 테스트를 갖춘다.

10. 가정과 제약

  • 회사 Confluence는 Cloud이며, 사용자는 API 토큰을 발급할 수 있다.
  • 사용자 PC에 git이 설치되어 있다.
  • Confluence 페이지 제목은 스페이스 안에서 유일하다(Confluence 규칙).
  • Windows 경로 길이 제한(260자)을 고려해 파일명을 줄일 수 있다.

11. 미결 사항

  • 회사 Confluence가 Cloud인지 Data Center인지 최종 확인 필요
  • clone 폴더를 사내 Git 서버에 올려 팀이 함께 쓰는 운영 방식을 허용할지
  • 사내 AI 도구 사용 정책 (사내 문서를 AI 도구에 넣는 범위)
