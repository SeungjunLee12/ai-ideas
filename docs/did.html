3. IF-02 Confluence REST API

Confluence Cloud REST API v2를 기본으로 하고, v2에 없는 기능만 v1을 쓴다. 기본 주소는 https://<site>.atlassian.net/wiki이다.

아래 경로와 필드는 설계 기준이다. 구현 시 Atlassian 공식 API 문서로 다시 확인한다.

3.1 인증

Authorization: Basic base64("<email>:<api_token>")
Accept: application/json
Content-Type: application/json

3.2 호출 목록

ID용도메서드 · 경로사용처
API-01토큰 검증 · 사용자 조회GET /rest/api/user/current (v1)login
API-02스페이스 조회GET /api/v2/spaces?keys={KEY}clone
API-03스페이스 페이지 목록GET /api/v2/spaces/{spaceId}/pages?limit=250[&body-format=storage]clone, pull
API-04페이지 단건GET /api/v2/pages/{id}?body-format=storagepull, push
API-05페이지 수정PUT /api/v2/pages/{id}push (M, 제목 변경)
API-06페이지 생성POST /api/v2/pagespush (A)

3.3 페이지네이션

v2 목록 응답의 _links.next가 있으면 그 경로(cursor 포함)로 다음 페이지를 요청하고, 없으면 끝낸다.

4. IF-03 git

시점명령
clonegit init -b confluence → git add -A → git commit → git branch main → git switch main
pull · push 전 자동 저장git add -A → git commit -m "wiki: 로컬 변경 저장" (변경이 있을 때만)
웹 상태 반영git worktree add .wiki/remote confluence (최초 1회) → 파일 쓰기 → git -C .wiki/remote commit
합치기git merge --no-edit confluence, 종료 코드 1 + git diff --name-only --diff-filter=U로 충돌 파일 확인
diffgit diff confluence -- <경로>

wiki가 만드는 커밋 메시지 형식은 DSD 6장을 따른다. .wiki/remote, .wiki/logs, .wiki/lock은 .gitignore에 넣는다.

6. IF-05 로컬 파일

사용자와 AI 도구가 지켜야 할 규칙이다. 자세한 형식은 DSD를 따른다.

  • front matter의 id는 수정하지 않는다. 지우면 새 페이지로 인식된다.
  • ```confluence-storage 블록은 내용을 바꾸지 않는다. 블록째 지우면 해당 매크로가 삭제된다.
  • 새 페이지는 원하는 부모 폴더에 .md 파일을 만들고 title만 적는다.
  • 폴더(하위 페이지가 있는 페이지)의 본문은 _index.md에 쓴다.
